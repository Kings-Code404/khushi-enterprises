# Render Deployment

## Included configuration

`render.yaml` creates a Node.js web service using `npm ci` and `npm start`. It sets Render's health check to `/healthz`, generates the JWT and session secrets, and prompts for all credentials instead of committing them.

## Deploy steps

1. Push the project, including `render.yaml`, `package-lock.json`, migrations and `.env.example`, to GitHub. Do not push `.env`.
2. In Render, select **New → Blueprint**, connect the GitHub repository, and apply the detected blueprint.
3. Enter the prompted MySQL, email, admin and Razorpay values in the Render dashboard. Set `FRONTEND_ORIGIN` and `RESET_BASE_URL` to your final `https://...onrender.com` or custom-domain URL.
4. Provision a managed MySQL database separately. Render's Blueprint database resources are PostgreSQL, while this project requires MySQL. Create the database first, grant the application user only the privileges it needs, allow Render network access, and set `DB_SSL=true` when the provider supports TLS.
5. Restore or initialise database data carefully. For an existing database, take a backup and apply `migrations/001_security_and_integrity_upgrade.sql` and `migrations/002_razorpay_payment_upgrade.sql` once. Never run `src/db/database.sql` in production because it drops tables.
6. After the first deploy succeeds, configure the Razorpay webhook as `https://YOUR-HOST/api/payments/razorpay/webhook` and test in Razorpay Test Mode.

## Environment variables

| Variable | Required | Notes |
| --- | --- | --- |
| `NODE_ENV` | Yes | Set to `production`. |
| `PORT` | No | Render provides it automatically; the app listens on it. |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | Yes | External MySQL database connection. |
| `DB_SSL` | Usually | Use `true` for a TLS-enabled managed database. |
| `JWT_SECRET`, `SESSION_SECRET` | Yes | Generated by the blueprint; keep private. |
| `FRONTEND_ORIGIN`, `RESET_BASE_URL` | Yes | Your final HTTPS app URL. |
| `EMAIL_*`, `ADMIN_*`, `RAZORPAY_*` | As used | Set only in Render's environment settings. |

## Free-tier behavior

Render free web services spin down after 15 minutes without incoming traffic. The first request after sleep can take longer while the service starts. `/healthz` is intentionally lightweight and can be used by Render's health check; it is not a keep-awake loop. A paid Render instance is needed for truly always-on behavior. The MySQL pool is created when the process starts and closed cleanly on Render shutdown/redeploy.
